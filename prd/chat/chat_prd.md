# AyuChat 聊天 PRD — 好友单聊 / 文本消息

> 版本：v0.1  
> 状态：草案  
> 适用范围：Desktop（先行）→ Android → Server / Connect

---

## 1. 文档目的

定义 AyuChat **v1 聊天**阶段的行为、数据模型与接口，覆盖：

- **好友关系**：互为好友后方可发起单聊（最短路径的好友申请 / 接受）
- **单聊会话**：两人之间唯一会话（`direct`）
- **文本消息**：发送、接收、历史拉取、失败重试
- **可扩展性**：消息类型、会话类型、富媒体载荷预留，**v1 不实现图片 / 文件**

本文与桌面端 `ChatComponent` 现有 UI 对齐；后端与 `connect` 按本文契约实现后，前端替换 `mockData` 即可。

## 2. 范围

### 2.1 v1 包含

| 能力 | 说明 |
|------|------|
| 添加好友 | 通过手机号搜索用户，发送好友申请 |
| 接受好友 | 在待处理列表中同意申请，建立双向好友关系 |
| 好友列表 | 查看已互为好友的用户，可从中发起聊天 |
| 单聊会话 | 两名好友之间自动对应一个 `direct` 会话 |
| 会话列表 | 展示最近会话、最后一条预览、未读数、时间 |
| 发送文本 | 输入纯文本，乐观展示，服务端持久化 |
| 接收文本 | 在线 WebSocket 推送；离线后通过历史接口补拉 |
| 历史消息 | 进入会话时分页向上加载 |
| 发送状态 | 己方消息：`sending` → `sent` / `failed`，失败可重试 |
| 断线提示 | 连接断开时禁止发送，展示重连入口（与现有 `ConnectionBanner` 一致） |

### 2.2 v1 不包含

| 能力 | 说明 |
|------|------|
| 图片 / 文件 / 语音 / 视频 | 消息模型预留 `type`，v1 仅实现 `text` |
| 群聊 | 会话模型预留 `group`，v1 仅实现 `direct` |
| 消息已读回执 | v1 仅「已发送」；已读为二期 |
| 消息撤回 / 编辑 | 二期 |
| 引用回复 / @ | 二期 |
| 会话置顶 / 免打扰 | 二期 |
| 消息全文搜索 | 二期 |
| 正在输入（Typing） | 二期（协议可预留事件名） |
| 陌生人私信 | **必须互为好友**才能发消息 |

### 2.3 设计原则（最短路径）

1. **先通再优**：REST 发消息 + WebSocket 收推送，不做复杂消息队列中间件。
2. **模型一次设计对**：`type` + `content` 结构从 v1 起固定，避免日后改表。
3. **幂等发送**：客户端带 `client_msg_id`，服务端去重，支撑失败重试。
4. **懒创建会话**：好友首次发消息或「发起聊天」时创建 `direct` 会话，不预生成空会话列表（除非产品明确要求空会话占位）。

## 3. 领域模型

### 3.1 好友关系（Friendship）

| 概念 | 说明 |
|------|------|
| 好友申请 | A 向 B 发起，`status = pending` |
| 互为好友 | B 接受后，双方各有一条 `accepted` 记录，或一张无向边表 |
| 聊天前置条件 | 仅 `accepted` 双向好友可创建会话、发消息 |

**最短路径规则**：

- 不能加自己为好友
- 不能向非注册用户发申请（返回 `USER_NOT_FOUND`）
- 已是好友：重复申请返回 `ALREADY_FRIENDS`
- 已有 pending 申请：返回 `FRIEND_REQUEST_PENDING`（或幂等成功）

### 3.2 会话（Conversation）

| 字段 | v1 | 说明 |
|------|----|------|
| `id` | ✅ | 会话 UUID |
| `type` | ✅ | v1 固定 `direct`；二期 `group` |
| `peer` | ✅ | 对方用户摘要（单聊专用展示字段） |
| `last_message` | ✅ | 最后一条消息摘要，用于列表预览 |
| `unread_count` | ✅ | 当前用户在该会话的未读数 |
| `updated_at` | ✅ | 最后活跃时间，列表排序依据 |

**唯一性**：`direct` 会话由 `(min(user_a), max(user_b))` 唯一确定，同一对用户全局仅一个会话。

### 3.3 消息（Message）— 可扩展核心

| 字段 | 类型 | v1 | 说明 |
|------|------|----|------|
| `id` | string | ✅ | 服务端消息 ID（雪花 / UUID） |
| `conversation_id` | string | ✅ | 所属会话 |
| `sender_id` | string | ✅ | 发送者 `user.id` |
| `type` | string | ✅ | v1 仅 `text`；预留见 [§3.4](#34-消息类型与-content-扩展) |
| `content` | object | ✅ | 类型相关载荷，JSON |
| `client_msg_id` | string | ✅ | 客户端幂等键（UUID），重试时不变 |
| `created_at` | string | ✅ | ISO 8601 UTC |
| `seq` | number | 建议 | 会话内单调递增序号，便于同步与分页 |

**v1 文本消息 `content` 示例**：

```json
{
  "text": "你好，这是普通文本消息。"
}
```

客户端展示字段映射（与现有 `ChatMessage` 对齐）：

| 服务端 | 客户端 `ChatMessage` |
|--------|----------------------|
| `id` | `id` |
| `content.text` | `text` |
| `sender_id === me` | `self: true` |
| 发送流程本地状态 | `status: sending \| sent \| failed` |

### 3.4 消息类型与 content 扩展

v1 **只实现 `text`**，但类型枚举与校验从第一天固定：

| `type` | v1 | `content` 结构（草案） |
|--------|----|------------------------|
| `text` | ✅ | `{ "text": string }` |
| `image` | 预留 | `{ "url", "thumb_url", "width", "height", "mime" }` |
| `file` | 预留 | `{ "url", "name", "size", "mime" }` |
| `audio` | 预留 | `{ "url", "duration_ms" }` |
| `system` | 可选 | `{ "text": string }` 居中系统提示 |

**扩展约定**：

- 未知 `type`：客户端展示「[不支持的消息类型]」，不崩溃
- 上传类消息（图片 / 文件）：二期走独立上传接口，消息体只存引用 URL + 元数据
- 服务端校验：`type` 与 `content` schema 必须匹配，否则 `400 INVALID_MESSAGE_CONTENT`

### 3.5 会话类型扩展

| `conversation.type` | v1 | 说明 |
|---------------------|----|------|
| `direct` | ✅ | 两人单聊 |
| `group` | 预留 | 群 ID、群名、成员列表等二期定义 |

## 4. 用户流程

### 4.1 添加好友 → 接受 → 发起聊天

```
/chat → 点击「+」→ 新增好友
  → 输入对方手机号（+86）
  → 搜索 / 直接提交申请
  → 成功：提示「已发送好友申请」
对方登录 → 待处理申请列表 → 同意
  → 双方成为好友
任一方 → 好友列表 → 点击好友
  → 打开或创建 direct 会话 → 进入聊天页
```

### 4.2 发送文本消息

```
选中会话 → 输入框输入文本 → Enter 或点击发送
  → 客户端立即插入气泡（status=sending）
  → POST 发送接口（带 client_msg_id）
  → 成功：status=sent，更新会话预览
  → 失败：status=failed，展示重试按钮
  → 对方在线：WebSocket 推送 message.new
```

**规则**：

- 空内容 / 纯空白：禁止发送
- 非好友：接口拒绝 `NOT_FRIENDS`
- 断线：不发起请求，本地 `failed`（与现有 mock 行为一致）
- 单条文本长度上限：建议 4000 字符（可配置）

### 4.3 接收与未读

```
对方发消息 → 服务端持久化 → 推送给在线接收方
  → 若当前未打开该会话：unread_count + 1，列表预览更新
  → 若正在该会话：自动标记已读（v1 仅清未读计数，无已读回执）
离线 → 下次登录拉会话列表 + 按需拉历史
```

### 4.4 加载历史

```
进入会话 → GET 最新消息一页（如 30 条）
  → 滚动到顶部 → 用 before_seq / before_id 加载更早消息
  → 无更多：展示「没有更多消息」
```

### 4.5 失败重试

- 重试时 **复用同一 `client_msg_id`**，服务端幂等
- UI：点击红色感叹号 → `sending` → 重新请求

## 5. 实时通道（WebSocket）

### 5.1 连接

- URL：`ws://host/api/v1/ws`（生产 `wss://`）
- 鉴权：连接时携带 `Authorization: Bearer <access_token>`（Query 或首帧 `auth` 消息，实现择一）
- 断线：客户端指数退避重连；重连成功后补拉会话与活跃会话增量

### 5.2 v1 服务端 → 客户端事件

| 事件 | 说明 |
|------|------|
| `message.new` | 新消息（完整 Message 对象） |
| `conversation.updated` | 会话预览 / 未读变化（可选，可由 `message.new` 推导） |
| `friend.request` | 收到好友申请（可选，v1 可轮询代替） |
| `friend.accepted` | 好友申请被接受（可选） |

### 5.3 v1 客户端 → 服务端

v1 **不要求**经 WebSocket 发消息（走 REST 即可）。二期可考虑 `message.send` over WS。

## 6. 客户端架构约定

### 6.1 分层

| 层 | 职责 |
|----|------|
| UI（`ChatComponent`） | 列表、气泡、输入、乐观 UI、重试 |
| 状态（store / hooks，二期可引入） | 会话与消息缓存、未读聚合 |
| connect | `friend.*`、`conversation.*`、`message.*`、WebSocket 客户端 |
| Server | 持久化、好友校验、推送 |

### 6.2 与现有 UI 对齐

桌面端已实现：

- 双栏布局、会话搜索、草稿按会话隔离
- 消息 `sending / sent / failed` 与重试
- `ConnectionBanner` 断线模拟（接入后改为真实 WS 状态）

接入时需替换：

- `MOCK_CONVERSATIONS` / `SEED_MESSAGES` → connect 拉取
- `queueSend` 定时器 mock → 真实 `POST /messages`
- `setConnection` mock → WebSocket 连接状态

### 6.3 connect 层职责

- 扩展 `connect/src/types.ts`：Friend、Conversation、Message、WS 事件类型
- 统一错误映射为 `ConnectError`
- WebSocket 单例：自动重连、事件分发到订阅者
- **不在 UI 组件内直接 `fetch` / `WebSocket`**

---

## 7. 服务端要点（最短路径）

| 模块 | v1 实现 |
|------|---------|
| 存储 | 关系型 DB：users（已有）、friendships、conversations、messages |
| 好友 | 申请 / 接受 / 列表 |
| 会话 | `direct` 懒创建；列表按 `updated_at` 倒序 |
| 消息 | 插入 messages 表；更新 conversation 摘要；递增 seq |
| 推送 | 内存或 Redis Pub/Sub 将消息 fan-out 到在线连接（单实例可先内存） |
| 鉴权 | 所有聊天 REST / WS 需登录；操作范围校验「本人会话 / 本人好友」 |

**不做（v1）**：

- 独立消息队列（Kafka 等）
- 多端同步复杂冲突解决（依赖 `client_msg_id` + `seq` 即可）
- 对象存储（图片文件二期）

## 8. 安全与权限

| 项 | 要求 |
|----|------|
| 发消息 | 发送者 ∈ 会话成员；`direct` 且双方互为好友 |
| 读消息 | 仅会话成员可拉历史 |
| 好友申请 | 不能骚扰：可选频控（同一对用户 24h 内 1 次申请） |
| 内容 | v1 纯文本；服务端可做长度校验；敏感词二期 |
| 传输 | 生产 HTTPS / WSS |

## 9. 状态与边界

### 9.1 空状态

| 场景 | 表现 |
|------|------|
| 无好友 | 引导「添加好友」 |
| 无会话 | 列表空态 + 「暂无会话」 |
| 会话无消息 | 「打个招呼吧」（与 UI 总方案一致） |

### 9.2 并发与顺序

- 同一会话内以 `seq` 或 `created_at` 排序
- 客户端合并：本地 `sending` 消息与服务器确认后的消息按 `client_msg_id` 去重替换

### 9.3 Token 过期

- REST / WS 鉴权失败 → connect 尝试 refresh → 失败则退出到登录页

### 9.4 对方注销 / 不可用

- 好友关系保留或标记失效（TBD）；会话只读或提示「对方账号不可用」

## 10. 验收标准（v1）

- [ ] 用户 A 可通过手机号向 B 发送好友申请，B 接受后双方好友列表可见对方
- [ ] 非好友无法向对方发消息
- [ ] A 向 B 发送文本，B 在线时实时收到；B 离线时上线后可拉到
- [ ] 会话列表展示最后一条预览、时间、未读数；进入会话后未读清零
- [ ] 发送失败可重试，且不产生重复消息（幂等）
- [ ] 历史消息可分页向上加载
- [ ] 断线时不能发送，恢复连接后可继续
- [ ] 消息 `type=text` + `content.text` 与协议一致；预留 `image` 类型不被 v1 实现但不破坏解析
- [ ] 桌面端移除 mock 后，核心流程可走通
